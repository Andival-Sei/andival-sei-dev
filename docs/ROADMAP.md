# Roadmap

Документ фиксирует поэтапный план развития портфолио-сайта Andival-Sei. Сроки оценочные и предполагают работу одного разработчика с выделением времени на ревью и тестирование.

## Этап 0. Срочные исправления (1 неделя)

1. **Перекодировать весь текст в UTF-8.** Пересохранить `.tsx`, `.ts`, `.css`, `.md` и `.env` файлы в UTF‑8 без BOM, восстановив осмысленный русский текст в контенте, метатегах и README.
2. **Обновить SEO-метаданные.** После исправления кодировки заново заполнить `metadata`, Open Graph и JSON-LD (`src/app/layout.tsx`, `src/lib/structured-data.ts`), проверить локали `ru-RU` и расставить ключевые слова.
3. **Починить показ раздела «Избранные проекты».** Добавить защиту от пустого списка в `src/components/sections/featured-projects.tsx`, показывать fallback-карту/приглашение добавить проекты и остановить авто-слайдер, когда элементов нет.
4. **Регрессивное тестирование.** Прогнать проект локально (`pnpm dev`, `pnpm build`, `pnpm test`), убедиться, что исправленный текст корректно отрисовывается и не вызывает ошибок рендера.

## Этап 1. База качества и инфраструктура (2 недели)

1. **Автоматизировать проверку качества.** Настроить GitHub Actions: lint (`pnpm lint`), типы (`pnpm tsc --noEmit`), тесты (`pnpm test:run`). Добавить отчёты об охвате `vitest` как артефакты.
2. **Ввести защиту ветки main.** Запретить прямые пуши, требовать успешного CI и код-ревью перед merge.
3. **Усилить статический анализ.** Расширить ESLint (набор `typescript-eslint`, `jsx-a11y`, `import`), включить строгие правила по доступности, незадействованным переменным, сортировке импортов.
4. **Стандартизировать форматирование.** Добавить `lint-staged` + `husky` с хуками `pre-commit` (lint + typecheck ограниченно на изменённых файлах), `pre-push` (тесты).

## Этап 2. Архитектура контента (3–4 недели)

1. **Перенести данные в контентный слой.** Вынести проекты, навыки, таймлайны в MDX/Contentlayer или Sanity/Notion API для последующего расширения без перекомпиляции.
2. **Добавить панель управления контентом.** Сделать простую админку (например, через `next-safe-action` + `supabase`) либо удобный процесс обновления MDX через Pull Request.
3. **Реализовать многоязычность.** Настроить i18n (Next.js middleware + `@lingui` или `next-intl`) для RU/EN версий, синхронизировать SEO-теги и hreflang.
4. **Стандартизировать структуры данных.** Ввести общие типы (`Project`, `Skill`, `TimelineEvent`), описать схемы Zod для валидации контента на этапе сборки.

## Этап 3. UX, доступность и производительность (2–3 недели)

1. **Медиа-оптимизация.** Конвертировать изображения в WebP/AVIF, создать адаптивные размеры, настроить оптимизацию видео (постер, lazy loading, webm/h264).
2. **Аудит доступности.** Прогнать Lighthouse/axe, исправить контрасты, фокус-стили, aria-атрибуты, обеспечить работу без мыши и с экранными считывателями.
3. **Микроанимации и интерактив.** Упростить тяжёлые эффекты (например, `tech-grid`), внедрить фреймворк анимаций (`framer-motion`), но с Progressive Enhancement.
4. **Измерение производительности.** Настроить Vercel Analytics + `next/script` для Web Vitals, добавить алерты в Slack/Telegram.

## Этап 4. Рост и интеграции (4–6 недель)

1. **Блог/кейсы.** Добавить раздел с публикациями (MDX + метки), связать с проектами и SEO.
2. **Интеграция форм обратной связи.** Подключить контактную форму через Supabase, Resend или Formspree, добавить спам-фильтры.
3. **Расширенные схемы Schema.org.** Сгенерировать `Article`, `Project`, `BreadcrumbList`, `Person`, `Organization`, `FAQ` там, где это повышает CTR.
4. **Автоматизация маркетинга.** Подключить социальные превью (OG Image на лету через `@vercel/og`), настроить рассылку/подписку (Buttondown, MailerLite).

## Контроль прогресса

- После каждого этапа фиксировать состояние в `docs/changelog.md`, вести ретроспективы.
- Поддерживать актуальный бэклог в GitHub Projects: колонки «Now / Next / Later».
- Ежемесячно проводить технический аудит (долг, метрики Lighthouse, SEO-рейтинги, позиции ключевых запросов).
